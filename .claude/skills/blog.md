# /blog — Full Blog Post Workflow

Orchestrate the complete pipeline for creating and publishing a new blog post on nerdstein.net: research → author → design → edit → build → push → deploy.

## Trigger

User runs `/blog` with a topic or idea. Examples:
- `/blog on why AI pair programming changes how senior engineers mentor juniors`
- `/blog Running 500 miles in a year: what I learned`
- `/blog The case against Drupal distributions`

## Workflow

Execute these steps in order, showing progress to the user at each stage.

---

### Step 1: Research

Invoke the **researcher** agent with the topic.

Ask it to surface:
- 2–3 relevant books with applicable quotes or ideas
- 2–3 sharp quotes from credible sources
- Any relevant data points or named examples

Show the research brief to the user and ask: "Does this capture the right angle? Any sources or ideas you want to add before I write?"

Wait for confirmation or adjustments before proceeding.

---

### Step 2: Author

Invoke the **author** agent with:
- The original topic/idea
- The approved research brief from Step 1

The author will:
- Write a complete draft following Adam's voice and style
- Save it to `content/blog/{slug}.md`
- Report the file path

Show the draft to the user in the terminal (or note the file path for review in the IDE).

Ask: "Review the draft in your editor. Any changes before editing and publishing? (say 'looks good' to continue, or tell me what to adjust)"

---

### Step 3: Design (optional, ask user)

Ask: "Do you want a category icon or illustration for this post? (yes/no)"

If yes, invoke the **designer** agent to:
- Identify which category icon applies based on the post's tags
- Check if `static/images/icon-{tag}.svg` already exists
- If not, generate it and save it
- Confirm the icon path so it can be referenced in the post

---

### Step 4: Edit & Review

Invoke the **editor** agent with the saved markdown file content.

The editor will:
- Check voice, structure, formatting, and substance
- Return either a clean revised draft or annotated issues

If **Status: Ready to publish** → continue.
If **Status: Needs revision** → show the editor's notes to the user and ask how to proceed.

Apply any revisions and re-save the file.

---

### Step 5: Build & Verify

Run the Hugo build to verify the new post compiles cleanly:

```bash
cd /Users/nerdstein/Projects/nerdstein-net-static
hugo --minify 2>&1
```

Check for:
- Zero ERRORs or WARNs related to the new post
- The new post appears in the page count (should increase by 1)

If errors, fix them before proceeding.

Preview the post URL: `http://localhost:1313/blog/{slug}/`

Optionally run `hugo server` and show the user the local URL for final visual review.

---

### Step 6: Commit & Push

Stage and commit the new post (and any new SVG assets):

```bash
git add content/blog/{slug}.md
git add static/images/  # if new icons were generated
git commit -m "Add: {post title}"
git push origin main
```

---

### Step 7: Deploy confirmation

After push, Cloudflare Pages will auto-deploy. Remind the user:

"Your post is deploying to nerdstein.net. Cloudflare Pages typically takes 60–90 seconds. The live URL will be: https://nerdstein.net/blog/{slug}/"

---

## Quick mode

If the user adds `--quick` flag (e.g., `/blog --quick My topic`), skip Steps 1 (research) and 3 (design) and go straight to drafting, editing, building, and pushing. Good for short personal posts that don't need intellectual backing.

## Manual post creation (no AI drafting)

If the user wants to write the post themselves:
1. Create the frontmatter stub: `content/blog/{slug}.md`
2. Open it in their editor
3. When they're done and say "ready", run Steps 4–7

## Frontmatter template

Always generated by the author agent, but here for reference:

```yaml
---
title: "Post Title"
date: YYYY-MM-DD
slug: "url-slug"
tags: ["tag1", "tag2"]
description: "One sentence, under 160 chars."
draft: false
---
```
